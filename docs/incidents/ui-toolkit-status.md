# UI Toolkit — Version Gate and Adoption Status

Moved verbatim from `.claude/CLAUDE.md` on 2026-10-08; the rule it supports is stated there in short form.

- **UI Toolkit is version-gated: game UI on Unity 6 (6000.0)+, Editor tools only below Unity 6.** Read `ProjectSettings/ProjectVersion.txt` before choosing — never assume the version. Even on Unity 6 it is per screen type, not a blanket switch: full-screen menus / settings / shop / popups / lists → UI Toolkit; world-anchored and Animator/Timeline-driven UI → UGUI; custom-shader UI Toolkit only from 6000.3, world-space UI Toolkit only from 6000.5 in this template. Rules, routing table and the field-measured traps (a `var()` in an inline UXML `style=` fails the whole clone; a transition on a theme swap exhausts `Allocator.Domain`; the Editor fills missing glyphs from OS fonts so multilingual text is only judged in a build): `rules/ui-toolkit-runtime.md`. The MIT design system `com.sinanata.designsystem` is the recommended component base, installed as a **pinned** UPM git dependency and never copied into `Assets/` — its C# auto-attaches via `[RuntimeInitializeOnLoadMethod]` and logs through `Debug.Log`, which is fine for a third-party package and would trip content hooks as vendored game code.
  > **Status (2026-09-30): enough to start converting menus, settings, popups and HUD — with one blocker.** Written and agent-tested: screen/popup infrastructure (`ui-toolkit-runtime.md` Card 13: `IScreenService`, `ScreenView`, one `UIDocument` per screen), motion (Card 14: `Motion.uss`, `UssTransition`), MVVM-with-R3 routing (Card 11), scene transitions and cross-scene data (`bootstrap-pattern.md` Card 7); full code in `skills/systems/ui-toolkit/SKILL.md` → "Screens, Popups and Motion". A baseline agent working from the files as they were before these cards produced six compile-clean defects (invisible popup panel, never-injected Views, menu wired into the Bootstrap scope, durations duplicated in C#, click-through backdrop, `OnEnable` race); the same task after them produced none. **Blocker, open:** `/setup-project` emits no R3 reference — the Games asmdef lacks it and the NSubstitute test asmdefs (`overrideReferences: true`) do not list `R3.dll` — so the first ViewModel (Settings) and its EditMode test do not compile. Fix that, and run the compile probe, before the first real conversion. **Open, not blocking:** (1) the framework's `LogTag` enum is closed, so `LogTag.UI` cannot exist — the skill uses `LogTag.General` until the package offers a game-side tag, contradicting `logging.md` Card 3; (2) Card 14's four "not yet measured" items are verified in the first project that adopts it, not in this template; (3) no list-screen (shop/inventory) pattern yet — how a changing item list reaches `ListView` (`ReactiveProperty<IReadOnlyList<T>>` vs `ObservableCollections`) is undecided; (4) mapping an existing HUD's DOTween/Animator animations to USS vs C# tween is per-project work. **Testing trap found here:** a subagent told to "read these files first" skipped the reads when stale copies of the rules were already in its context, and designed from the pre-edit versions — a prompt test run in the same session as the edit must say the in-context copies are stale and require `Read` from disk, or it measures the old text.
