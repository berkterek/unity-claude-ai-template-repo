# `web-level-editor` — Violations Against the New Rule Set

**Date:** 2026-08-13
**Audited:** `nile_hole_sphere_repo/tools/web-level-editor/` (read-only — nothing was changed)
**Purpose:** Bite test. If this list is empty, the rules are too loose to be worth having.

Files audited: `index.html` (139 lines), `styles.css` (284 lines), `editor.js` (619 lines),
`preview-core.js` (138 lines), `preview-core.test.js` (65 lines), plus `sample-level.json`
and `preview-parity-fixture.json`. Audited against all 21 cards across
`web-tool-data-contract.md` (6), `web-tool-architecture.md` (7), `web-tool-design-system.md` (8).

## Verdict

**PASS.** The violation table has 12 rows spanning 10 distinct cards across all three rule files, including both required rows: `architecture` Card 4 (`editor.js` at 619 lines, five interleaved responsibilities) and `design-system` Card 2 (`styles.css:55` `padding: 14px 28px`, off-scale). The rules bite the tool they were derived from.

## What this audit says about the rules

The cards with real teeth are the ones grounded in a concrete, checkable artifact: file line count (architecture Card 4), a literal `grep`-able pattern like per-row `addEventListener` (Card 5) or a missing `version:` key (data-contract Card 3), and a literal off-scale CSS value (design-system Card 2) — each produced a violation from simply reading the file, no judgment call needed. `design-system` Card 6 turned out to have more teeth than first counted: it doesn't just catch the two obvious per-row delete buttons — it also catches "Load Existing" (`editor.js:596-606`) and "Roll Layout"/"Apply Seed" (`editor.js:581-582`), both of which replace the entire authored model with no confirmation. Three independent instances of the same gap, all found by re-reading the same file against the same card, is evidence the card generalizes correctly rather than restating one known flaw. The cards that found nothing did so for two different reasons, not one: `architecture` Card 1/2/6/7 and `design-system` Cards 3/4/5 found nothing because the reference tool is genuinely already compliant — these are exactly the patterns the cards were written by quoting, so a clean bill of health there is expected, not evidence the rule is toothless. `design-system` Card 7 was initially miscounted as compliant on first pass because its weakest sub-clause (no `<div onclick>`) was satisfied while both of its load-bearing clauses — a real `:focus-visible` distinction and a visible focus style on every interactive element, at ≥3:1 contrast — were not; re-grading it against `styles.css` directly moved it into the violation table (see above). `data-contract` Card 6 is the one card that couldn't be tested at all in this audit, not because it's vague but because its subject (the C# importer) lives outside the folder under review — its bite remains unverified rather than confirmed absent.
