# PLAN — ARCHITECTURE.md for `_Framework/` subfolders

**Status:** DONE 2026-09-02 · **Created:** 2026-09-02 · **Raised by:** the save/load + logging adoption

## The gap

`rules/architecture.md` requires an `ARCHITECTURE.md` in every `Games/Concretes/<Domain>/`. `_Framework/` is
outside that rule — deliberately at the time it was written, because `_Framework/` held only `Events/`.

It no longer does. `/setup-project` Step 4 now generates `Logging/` and `SaveLoadSystems/` as well, and both
carry decisions a reader cannot recover from the code:

| Folder | The decision that is invisible in the code |
|---|---|
| `SaveLoadSystems/` | why the `*Dal` split exists at all (a cloud backend must be addable without touching a service), and that the DAL is the **only** legitimate `File`/`JsonConvert` site in the project |
| `Logging/` | why `Error` is neither `[Conditional]` nor tag-filtered while `Log`/`Warning` are — currently recorded only as a comment inside `DLog.cs` |
| `Events/` | why `EventBusAccessor` is the single approved static accessor, and that no second one may be added |
| `Editors/` | that it is `includePlatforms: ["Editor"]` and must never be referenced from a runtime assembly |

The `DLog.cs` comment is the warning sign: a load-bearing design decision is sitting in a source comment
because there is nowhere else for it to go. That comment survives only as long as nobody "tidies" the file.

## What to do

Add one `ARCHITECTURE.md` per `_Framework/` subfolder, generated by `/setup-project` Step 4 alongside the
`.cs` files, following the same contract the `Concretes/` docs already use:

```
## Purpose          ← one sentence; if it needs "AND", the folder is two folders
## Boundary         ← what this assembly never does, and who owns that instead
## How to extend    ← the SHAPE of an extension: which interface, which folder, which registration
## Gotchas          ← the mistake people actually make here
```

Same hard cap of 40 lines. Same prohibition on class-name-like symbols — describe shape, not names, so a
rename cannot rot the doc. `/knowledge-graph implementers <interface>` already owns the inventory half.

## What has to change to support it

1. **`rules/architecture.md`** — extend the ARCHITECTURE.md section to cover `_Framework/<Subfolder>/`, and
   say why the reasons differ from the `Concretes/` case: a `Concretes/` domain documents a *feature
   boundary*, a `_Framework/` folder documents an *assembly boundary*, which is stricter (an `.asmdef` flag
   is per-folder and unenforceable per-file).
2. **`check-architecture-doc.sh`** — today Trigger B hard-blocks any `ARCHITECTURE.md` outside
   `Games/Concretes/`, and blocks one under `Abstracts/` by name. A `_Framework/Logging/ARCHITECTURE.md`
   would therefore be **rejected**. The path check has to admit `_Framework/<Subfolder>/` before any doc can
   be written at all — this is the first thing to change, or step 3 cannot even be committed.
3. **`/setup-project` Step 4** — emit the four docs with the generated code, so a new project starts with
   them rather than acquiring them later, if ever.
4. **Migration of the `DLog.cs` comment** — move the `Error`-is-not-conditional rationale into
   `Logging/ARCHITECTURE.md` under `## Gotchas`, and leave a one-line pointer in the source. The comment is
   currently the only record; do not delete it before the doc exists.

## Sequencing

2 → 1 → 3 → 4. The hook has to stop rejecting the path first; everything else is inert until then.

## Not in scope

Do not add an `ARCHITECTURE.md` at the `_Framework/` root. Same reason `Concretes/` has none: one doc per
assembly boundary, and the root is not one — it is a container for four independent assemblies whose whole
point is that they do not reference each other.

## Done — 2026-09-02

All four steps landed, in this order: hook first, then the rule, then the generator, then the comment.

1. `check-architecture-doc.sh` validates `_Framework/<Subfolder>/` in both triggers. The scope test is
   **ownership of an `.asmdef`**, not a skip list — `Installers/` is exempt automatically because it owns
   none, and a folder that later gains one starts being asked for a doc that same day. A doc at the
   `_Framework/` root is blocked explicitly. 10 new bats cases (30–39), including one that pins the
   `Games/Concretes/` behaviour as unchanged.
2. `rules/architecture.md` — the section no longer contradicts itself. It now states *why* the reason
   differs: a `Concretes/` doc records a feature boundary, a `_Framework/` doc records an assembly
   boundary, and an assembly boundary is a physical fact rather than a convention.
3. `/setup-project` Step 4 emits four docs (`Events`, `Logging`, `SaveLoadSystems`, `Editors`). Each was
   extracted and run through the hook: 4/4 exit 0, longest 26 lines against the 40 cap.
4. The `DLog.cs` rationale moved into `Logging/ARCHITECTURE.md` → `## Gotchas`. The source keeps the
   prohibition ("do not restore the gate or the attributes") and a pointer; only the story moved, because
   the prohibition has to be readable at the exact line someone is about to edit.

**One correction to this plan's own premise.** Step 2 above recorded that the hook *blocked* a
`_Framework/` doc and therefore had to change before anything else could be committed. Measured: it did
not block — it fell through to `exit 0`, silently accepted and never validated. That is worse than a
block, because nothing tells the author their doc went unchecked, and it means steps 3 and 4 were never
actually gated on step 2. The sequencing still turned out right; the reason given for it was wrong.
